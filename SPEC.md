# plan-diff: SPEC

Written 2026-10-05 from the SPEC interview with Alex (Session B), ROADMAP.md section 7, and
`series-docs/RESEARCH-plan-diff-sources.md` (checked 2026-10-05). Roadmap name: Project 2. This file wins from here on.

## 1. Business outcome

Every fall a broker has to tell each Medicare Advantage client whether next year's plan still fits. The answer is buried
in 300-page carrier documents with no standard layout. plan-diff reads those public documents into one canonical plan
record where every value cites its document and page, checks each value against CMS's official benefit data, diffs
2026 against 2027, and raises a "shop again" flag a broker can act on and defend.

Terms, once:
- **PBP (Plan Benefit Package) data:** CMS's public, official file of every Medicare Advantage plan's benefits, by plan ID and year.
- **Crosswalk:** CMS's public file saying which plan ID becomes which next year. A plan that vanishes may have been merged, not ended.
- **SB, EOC, ANOC:** the carrier's Summary of Benefits, Evidence of Coverage, and Annual Notice of Change PDFs.

## 2. Decisions locked in the interview (2026-10-05)

1. **Slice:** Medicare Advantage, Texas, plan years 2026 vs 2027. Humana Gold Plus H0028-030 (HMO, San Antonio) and
   Wellcare (Superior HealthPlan) H5294-014 (HMO). Spares: H5294-016 and a second Humana Texas plan. If any 2027 PDF
   is not live when PR 2 runs, the slice falls back to 2025 vs 2026 and the README says so.
2. **Source documents are never committed.** The repo holds `sources/manifest.json` (URL, SHA-256, size, retrieved date,
   carrier, plan, year, document type). `plan-diff fetch` downloads each file once, slowly, into git-ignored
   `data/raw/`, and refuses a file whose hash differs from the manifest. The repo commits only extracted values with
   page citations. Tests use CMS data and small synthetic PDFs generated by code.
3. **Fields, v1 (15):** monthly premium, medical deductible, maximum out-of-pocket (in network), PCP copay, specialist
   copay, emergency room, urgent care, inpatient stay, outpatient surgery, drug deductible, drug tier 1, tier 2, tier 3,
   dental allowance, OTC allowance. Each field is a typed value (money as Decimal, a copay or coinsurance or "not
   covered") plus a unit (per visit, per day, per year).
4. **Shop-again flag.** Always: plan terminated or consolidated per the CMS crosswalk (never inferred from a missing
   plan ID), service area lost a county, or a v1 benefit removed. Thresholds (in `config.py`): premium up $20 or more a
   month, maximum out-of-pocket up $1,000 or more, drug deductible up by any amount. Each flag lists its reasons.
5. **PDF vs CMS disagreement: flag it, never pick.** Both values, the PDF page, and the CMS row go to the review queue
   with low confidence; the accuracy table counts a mismatch.
6. **Defaults accepted:** Jev recording only with Alex's yes, capped at $0.50 per session; the LLM extraction fallback
   is built but off until Alex adds a key and a cap; ACA is out of v1 (listed as next); PDF tools are pdfplumber (MIT)
   and pypdf (BSD-3), never PyMuPDF (AGPL); the first dashboard screen answers "Which plans changed enough that a client
   should shop again?"; before the first real download Alex sees the exact files, sources, and sizes and says yes;
   one changelog fragment per PR under `changelog.d/`.

## 3. Users and what each needs to see

- **Broker or account manager:** which plans changed enough to call the client about, and why, with the page to quote.
- **Ops or data lead:** which extracted fields are trusted, which disagree with CMS, what is in the review queue.
- **Engineer or hiring manager:** the accuracy table per field and method, and the provenance on every value.

## 4. Out of scope (v1)

ACA plans (next); client-level disruption reports (that is the capstone, joined with bob-resolve's golden records);
drug formulary lookups for specific drugs; provider network changes; any personal data; committing carrier PDFs;
states beyond Texas; fields beyond the 15.

## 5. Inputs

- **CMS, public domain:** PBP benefits data 2026 and 2027, MA Landscape 2026 and 2027, Part C and D Crosswalk 2027,
  service area files. Small filtered extracts for the chosen plans are committed under `fixtures/cms/` with the source
  URL, file name, and retrieved date in a `SOURCE.md`; the full downloads stay in `data/raw/`.
- **Carrier PDFs, public, copyrighted:** SB, EOC, ANOC per plan per year (about 12 files, roughly 1,000 to 1,500 pages),
  referenced only by manifest.
- **Synthetic PDFs:** generated by test code (a small SB-shaped document with a cost-sharing table) so CI never needs
  a real carrier file.

## 6. Pipeline

1. **Fetch** by manifest, hash-checked, rate-limited, never in CI.
2. **Classify** each document: carrier, document type, plan ID, plan year. Deterministic first (plan ID pattern
   `H\d{4}-\d{3}`, title text); Jev `choice` only when the deterministic classifier is unsure.
3. **Deterministic extraction:** pdfplumber over known section headers and cost-sharing tables, one parser per field
   family, each value with document id, page number, and method `rule`.
4. **LLM fallback** (built, off): only for fields the rules could not read, page text in, strict schema out, method `llm`.
5. **Agreement check:** where both a rule value and an LLM value exist, Jev `noul` "do these agree?"; disagreement goes
   to review.
6. **Validate against CMS PBP:** every field compared; match, mismatch (review, decision 5), or not in PBP.
7. **Diff** 2026 vs 2027 keyed by crosswalk (old plan ID to new plan ID), with a change category per field and the
   shop-again flag per decision 4.

## 7. Run outputs

`manifest.json` (inputs and hashes, versions, mode per tier, Jev and LLM usage and cost), `plans/<plan>_<year>.json`
and `plans.parquet` (canonical records, every field with document, page, method, confidence), `validation.json`
(per field: PDF value, CMS value, verdict), `accuracy.json` (per field and method), `diff/<plan>.json` (changes and
shop-again flag with reasons), `review_queue.jsonl`.

## 8. Dashboard pages and the one question each answers

- **Overview:** Which plans changed enough that a client should shop again? (flagged plans first, reasons, counts)
- **Plan comparison:** What exactly changed between 2026 and 2027 for this plan? (15 fields side by side, change category)
- **Changes by category:** Where are costs moving across plans? (premium, MOOP, copays, drugs, allowances)
- **Trust:** Which values can a broker quote? (accuracy table, review queue, PDF vs CMS mismatches)
- **Document viewer:** Show me the page. (each value links to its document and page; the PDF itself is loaded from
  the carrier URL, never served from this repo)

## 9. Concrete examples (each becomes a test)

1. **Happy path, synthetic.** A generated SB-shaped PDF for a fake plan H9999-001 in two years with a known premium
   change from $0 to $25. Extraction reads all 15 fields with correct page numbers; the diff shows premium up $25; the
   shop-again flag fires with reason "premium up $25 a month".
2. **Must not call it a termination.** A plan ID present in 2026 and absent in 2027 whose crosswalk row says
   "consolidated into" another ID. The diff follows the crosswalk to the new ID; the flag reason is "plan consolidated",
   not "plan terminated".
3. **Real termination.** A crosswalk row marked terminated (from the committed CMS extract). The flag fires with
   reason "plan terminated" and the CMS file row as evidence.
4. **Must flag, not pick.** A synthetic PDF says specialist copay $45 while the committed CMS extract for that plan says
   $40. Both values appear in `validation.json`, the field lands in `review_queue.jsonl` with low confidence, and the
   accuracy table counts one mismatch.
5. **Below threshold, no flag.** Maximum out-of-pocket rises $500 and nothing else changes. The change is reported in
   the diff; the shop-again flag stays off.
6. **Must refuse, hash mismatch.** `plan-diff fetch` given a file whose SHA-256 differs from the manifest refuses it,
   writes nothing to `data/raw/`, and exits non-zero naming the expected and received hashes.
7. **Must never commit a carrier PDF.** A test fails if any `.pdf` outside `tests/` generated fixtures is tracked by git.
8. **Jev and LLM off.** With both off, documents the rules cannot classify or fields they cannot read go to the review
   queue, the run completes, and the manifest shows zero calls and zero cost.

## 10. End-to-end check

`npm run verify` green on synthetic PDFs and committed CMS extracts (examples 1 to 8). Then, on Alex's machine only, after
his yes on the download: `plan-diff fetch` plus `plan-diff run` on the real Texas slice produces the accuracy table and
the two plans' diffs; that run's outputs (not the PDFs) are committed as the demo run.

## 12. Guardian rules (every brief repeats these)

- Public documents only; no personal data anywhere. Never commit a carrier PDF; never serve one from the dashboard.
- Downloads only through `plan-diff fetch`, only after Alex's yes for the exact file list, never in CI or by a subagent.
- Jev and LLM default `replay` or `off`; recording only by the orchestrator after Alex's yes, within the cap.
- Never read `.env`. No push, repo creation, PR, or Vercel link without Alex's words for that action.
- Accuracy numbers are labeled with the slice and date. No em dashes.
